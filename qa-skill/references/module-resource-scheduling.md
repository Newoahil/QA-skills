# Module Resource Scheduling

Phase 2 M6 activates host-bounded resource scheduling for [`../project-qa-execute/SKILL.md`](../project-qa-execute/SKILL.md). Scheduling is deterministic Planning state. It does not authorize commands, change candidate policy, or convert unexecuted candidates into Execution Evidence.

## Resource Declarations

Module tasks have nonempty safe logical task IDs; duplicate, malformed, or secret-like task IDs are invalid authority, return `ok:false`, and produce no ambiguous waves. Module tasks declare structured logical resource IDs as `kind:id`. Canonical shared kinds are `database`, `port`, `file`, `credential`, `fixture`, `environment`, `cache`, `service`, and `external-system`; unknown resource kinds are invalid. Resource IDs must not contain raw secrets, tokens, passwords, credential values, connection strings, bearer tokens, API keys, URL userinfo, or personal data. Secret-like, malformed, and unknown resources are excluded from returned task resources, force serial handling, make the schedule `ok:false`, and emit redacted diagnostics that identify only task/index/category rather than raw rejected IDs.

Undeclared, missing, malformed, ambiguous, or unknown mutable resources serialize by default; unsafe resource declaration states also serialize by default. Each task must explicitly record `resource_declaration_state: declared`; a missing state is normalized to `missing`, secret-like arbitrary raw state is normalized to `unsafe`, and unsupported raw state is normalized to `malformed`. Raw supplied state values are not echoed. Anything other than `declared` serializes, is invalid authority, and makes the schedule `ok:false`. Shared mutable resources serialize unless every sharing task has a distinct isolation key with isolation evidence SHA-256 and byte count. Shared mutable resources also require an independently validated actual isolation evidence reference under a supplied artifact root. Isolation keys are nonempty safe logical IDs and never contain secret-like values. Isolation evidence uses safe target-relative or artifact-root-relative path handling and records actual SHA-256, byte count, and a full SHA-256 evidence identity derived from canonical path plus hash plus bytes. Independently validated distinct paths/identities may prove distinct isolation even when bytes match; same path, same identity, unsafe, missing, duplicate, or hash/byte-mismatched isolation evidence is invalid and cannot authorize parallel sharing.

## Host-Bounded Waves

Disjoint tasks are parallel-eligible, not automatically authorized. The scheduler forms deterministic waves in task order and caps each wave by the finite positive integer host-declared limit. A missing, zero, negative, non-integer, or non-finite host limit falls back to `1` with a visible reason; do not invent a universal maximum.

Tasks that share mutable resources without valid distinct isolation evidence are placed in serial waves but may still be `ok:true` when all declarations are otherwise valid. Any invalid authority, including malformed or duplicate task IDs, unsafe isolation keys, provided-but-invalid isolation evidence, malformed/unknown/secret resources, non-declared resource state, unsafe output paths, and output path collisions, returns `ok:false`. Any force-serial task is alone in its wave: the scheduler never adds another task after placing a serial task and never places a serial task into a nonempty wave. Tasks with undeclared or ambiguous resource state are serialized. Distinct safe result paths and artifact paths are required for parallel tasks. Duplicate or unsafe paths fail closed. Result/artifact paths are resolved under the supplied safe artifact/output root using root-bound canonical validation for missing leaves. Duplicate result paths, duplicate artifact paths, and result/artifact collisions are detected using canonical output identities, not lexical strings; unsafe paths include traversal, absolute, drive-qualified, UNC, NUL, missing or invalid roots, existing directory leaves, symlink/junction in any existing path component even when resolving inside root, parent realpath escape, leaf link, realpath escape, lstat/realpath race, or other unsafe output authority. Unsafe output authority returns `ok:false` and forces involved tasks serial without creating a fifth project status.

## Schedule Record

Each schedule records resource declarations, durable per-task `serial_reasons`, durable per-task `parallel_eligible_reasons`, effective host limit, fallback reason if any, deterministic waves, isolation evidence refs, result paths, artifact paths, and diagnostics. Serial reasons include invalid authority, shared-unisolated mutable resources, path collisions, force-serial handling, and host fallback when relevant. Parallel-eligible reasons include disjoint declared resources or shared resources with distinct validated isolation evidence, always noting the host bound and separate safe paths. Reasons are task-level records, not only aggregate diagnostics, and must not contain secrets or raw rejected inputs. The schedule must remain visible in the project report and conclusion, but it is not command authorization and is not execution evidence.
