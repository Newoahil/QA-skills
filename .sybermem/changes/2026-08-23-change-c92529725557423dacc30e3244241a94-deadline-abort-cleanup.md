## Change Content
Updated SDK deadline helpers in fixer, QA, and investigation specialist paths so timeout handling returns or rejects immediately with the deadline result. Session abort is still attempted, but it is now fire-and-forget best effort and cannot block the caller.

Added hung-abort regressions for fixer, QA, and specialist SDK prompts. Each test races the session runner against a short external timer and proves the runner settles before the hung abort cleanup can stall the process.

## Reason for Change
The review found that timeout code awaited `client.abort()` during cleanup. If the shared OpenCode server or SDK abort endpoint hung, the scheduler could remain inside the critical section and keep the N=1 lock held beyond the intended deadline.

## Impact Scope
This affects the shared OpenCode SDK session paths for fixer, QA, specialist investigation, and plan prompts. Child-process fallback remains unchanged. Timeout results now preserve the primary timeout error and no longer expose synchronous abort cleanup errors in the returned result.

## Implementation
Replaced awaited abort cleanup in deadline timers with `Promise.resolve().then(onTimeout).catch(() => undefined)`. The deadline result is produced immediately; abort cleanup failure is intentionally swallowed because it is no longer part of the blocking contract.
