## Change Content
`processPlanBuilder` now uses the OpenCode SDK session path (create session in the target dir,
prompt with json_schema) when a shared server is configured, instead of spawning an
`opencode run --attach` child process (which hung in the real E2E run). The scheduler passes
`opencodeClient` to `processPlanBuilder`. The child-process fallback remains for environments
without a shared server.

## Reason for Change
The real #211 E2E run showed that after the specialists completed investigation, the plan
builder (which still used the spawn--attach path) hung. 方案 A requires all agent invocations
(specialist, plan, fixer, qa) to use the shared SDK session model, not the flaky attach spawn.

## Impact Scope
Localized to investigation-process.mjs (plan builder) + scheduler.mjs (inject opencodeClient).
Full suite stays green.

## Implementation
Mirrors the specialist SDK path: create a `plan-<issue>` session with `directory: repoDir`,
prompt `guardian-business` with json_schema, extract JSON. Fallback to runAgentJson when no
opencodeClient.

## Test Verification
Full suite: 295/295 green. New test locks processPlanBuilder uses the SDK client (creates a
session in the target dir and prompts with json_schema) instead of spawning.

Found by the real #211 E2E run with the SDK runtime.
