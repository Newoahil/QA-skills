## Change Content

- `watch_mode: "new-open"`：scheduler 建立 creation baseline，只发现值守启动后新建的 Open issue；已有 `qa-guardian` 标签的 issue 保持兼容。
- 新 issue 领取后由 scheduler 添加 `qa-guardian`、`qa-guardian-claimed` 标签；标签是可见投影，JSON 状态仍是权威，领取失败不启动 agent。
- 新增 `/guardian followup <problem>`，仅允许可信作者、仅在 `DONE`/`GATE_2_WAIT` 生效，进入新的 `INVESTIGATING` round。
- 新 round 保存 `round_history`、递增 `processing_round`、记录 followup comment/data，清理当前轮次 branch/PR/risk/fix_rounds；不自动 reopen、不 force-push 旧 PR。
- 新增 scheduler-owned label projection，标签失败非致命，仅记录 warning。

## Reason for Change

用户希望创建新 issue 时不再手动加 label，并希望已处理 issue 在后续验收发现新问题时能开启第二轮，而不是被 DONE/GATE_2_WAIT 永久跳过或每轮重复处理。

## Impact Scope

值守发现、issue 可见标签、状态轮次与命令路由；保持 N=1、trusted author fail-closed、agent 不直接改标签、已有 labeled 模式兼容。

## Implementation

`commands.mjs` 增加 followup；`state-router.mjs` 增加 DONE/GATE_2_WAIT → INVESTIGATING newRound；`state.mjs` 增加 round/claim 字段和 `startFollowupRound`；`scheduler.mjs` 增加 creation cursor、labeled+new-open+followup candidates、new issue claim；`label-io.mjs` 管理可见投影标签；README/DEPLOY/design 文档同步。

## Test Verification

`node --test "tests/guardian/*.test.mjs"` → 146/146 pass。覆盖 followup 命令与轮次、状态 schema、label plan/projection、旧状态归一化及既有 Guardian 流程。

## Notes

默认仍可使用 `watch_mode: "labeled"`；目标项目已配置 `watch_mode: "new-open"`。`/guardian rework` 继续表示当前 Gate 2 PR 打回，`/guardian followup` 表示新验收轮次。
