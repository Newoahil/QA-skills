## Bug Description

The #211 fixer SDK session successfully read the approved dossier/plan and modified the target
source/test files, then stopped at an `apply_patch`/`grep` tool part with `status: pending`.
The headless server had no UI capable of answering the permission prompt.

## Root Cause

`createSession` supplied only three deny rules (`question`, `plan_enter`, `plan_exit`). Session-level
permission replaced/overrode the agent's complete frontmatter permissions, leaving edit/apply_patch/
bash in the default `ask` state. OpenCode headless attach does not relay those prompts reliably
(upstream issue #16367), so the session hung indefinitely.

## Solution

- Added complete role-specific permission matrices with no `ask` actions.
- Fixer (`qa-guardian`): edit/write/apply_patch allowed; merge/close/issue-edit/reset/clean/install
  and arbitrary task delegation denied; normal commit/push/checkout remain allowed.
- QA: edit/write/apply_patch denied; tests allowed; commit/push/install denied; only qa-facet task
  delegation allowed.
- Specialists/plan builder: product writes and arbitrary bash denied; read-only git/test shell
  commands allowed; task delegation denied.
- question/plan/doom-loop prompts are denied for every headless role.

## Prevention Measures

- Tests assert fixer can apply patches but cannot merge/install/delegate.
- Tests assert QA/specialists are read-only and no role contains an `ask` permission.
- SDK sessions must always receive a complete permission matrix, never a partial overlay.
