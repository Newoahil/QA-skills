## Description

After the launcher created a control worktree and its `.qa/guardian/config.json`, the next start
failed with `control worktree 不干净`. `git status --porcelain` reported the new Guardian state
config as a pending change, which the reuse check treated as external dirty work to protect.

## Root Cause

`Ensure-ControlWorktree` required the whole worktree to be porcelain-clean. But the control worktree
is the authoritative home of `.qa/guardian` state, lock file, and watch state; those are Guardian-owned
and must not be treated as user modifications to guard against overwrite. The tools repo
`supervisor-exec.mjs` already models this as a `GUARDIAN_ALLOWLIST`; the launcher did not.

## Solution

`Ensure-ControlWorktree` now filters `git status --porcelain` lines and ignores Guardian-owned
paths (`.qa/guardian/`, `.sybermem/`, `.scheduler.lock`, `watch-state.json`). It still fails closed
when any non-Guardian tracked or untracked path is dirty, preserving the protection against
overwriting real user or fixer work.
